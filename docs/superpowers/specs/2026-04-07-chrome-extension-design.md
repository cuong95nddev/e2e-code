# Chrome Extension Action Capture — Design Spec

Date: 2026-04-07

## Overview

Replace the current system-wide uiohook action capture with a Chrome extension that records both the tab video and rich DOM-level action events. The extension handles recording + event capture; Electron receives and stores everything. The existing analysis pipeline (frame extraction, Claude skill) is unchanged — but now the event data includes element text, selector, aria-label, etc., so Claude no longer has to guess what was clicked from a screenshot.

## Goals

1. Chrome extension captures tab video + DOM events with rich element context
2. Extension POSTs data to a local HTTP server in Electron (localhost:7878)
3. Electron saves `.webm` + writes events to SQLite — same storage layout as before
4. Analysis pipeline enriched: `analyze.md` rows now include element label + selector
5. No new npm packages required (Node built-in `http`, existing `better-sqlite3`)

## Out of Scope

- Firefox/Safari support
- System-wide capture of non-browser actions (uiohook remains for that use case)
- Replay / automation of recorded actions

## Architecture

```
Chrome Extension (MV3)
  content-script.ts     ← auto-injected, captures DOM events
  background.ts (SW)    ← drives session, buffers + POSTs events, sends video
  popup.html/ts         ← Start/Stop UI, connection status
        │
        │  POST localhost:7878/session/start
        │  POST localhost:7878/events          (500ms batches)
        │  POST localhost:7878/recording       (webm blob on stop)
        ▼
Electron: chrome-bridge.ts   ← Node http server, no new deps
        │
        ▼
recordings/<stem>/
  <stem>.webm            ← tab recording
  <stem>.db              ← SQLite with chrome_events table
  frames/                ← extracted by existing pipeline
  analyze.md             ← generated by existing pipeline
  result.md              ← generated by Claude skill
```

## Chrome Extension

### manifest.json

```json
{
  "manifest_version": 3,
  "name": "e2e-code Recorder",
  "version": "1.0.0",
  "permissions": ["tabCapture", "storage", "scripting"],
  "host_permissions": ["<all_urls>"],
  "background": { "service_worker": "background.js" },
  "content_scripts": [{
    "matches": ["<all_urls>"],
    "js": ["content-script.js"],
    "run_at": "document_idle"
  }],
  "action": { "default_popup": "popup.html" }
}
```

### content-script.ts

Listens with capture-phase event listeners. Does NOT intercept — only observes.

**Events captured:**

| Event | Trigger | Data |
|-------|---------|------|
| `click` | mousedown | element context, x/y, url |
| `input` | input (debounced 300ms) | final value, element context |
| `keydown` | keyboard | shortcuts only (Cmd+, Ctrl+, special keys) |
| `scroll` | scroll (throttled 200ms) | direction, scroll target |
| `navigation` | `pushState`/`popstate` hook | from_url → to_url |

**Element context extracted per click/input:**

```typescript
interface ElementContext {
  tag: string;           // "button", "input", "a", etc.
  id?: string;           // element id attribute
  text?: string;         // trimmed textContent (max 80 chars)
  aria_label?: string;   // aria-label attribute
  role?: string;         // role attribute or implicit ARIA role
  placeholder?: string;  // for inputs
  data_testid?: string;  // data-testid | data-cy | data-e2e (first found)
  selector: string;      // best CSS selector (see priority below)
  xpath: string;         // absolute XPath
  classes: string[];     // meaningful class names (exclude utility classes)
  bbox: { x: number; y: number; width: number; height: number };
}
```

**Selector priority** (matches Playwright's approach):
1. `[data-testid="..."]` / `[data-cy="..."]` / `[data-e2e="..."]`
2. `[aria-label="..."]`
3. `#id` (if id is not auto-generated)
4. `role=X[name="Y"]` format
5. Shortest unique CSS selector (walk up DOM, stop at first unique combo)
6. XPath as fallback

Events are sent to background via `chrome.runtime.sendMessage`.

### background.ts (Service Worker)

**Session lifecycle:**
1. User clicks Start → `chrome.tabCapture.capture()` → `MediaRecorder` (webm, vp8)
2. POST `localhost:7878/session/start` → Electron returns `{ sessionId, startTime }`
3. Store `startTime`; all events use `ts_ms = Date.now() - startTime`
4. Buffer incoming events, flush every 500ms via `POST /events`
5. User clicks Stop → `mediaRecorder.stop()` → collect full blob
6. POST `localhost:7878/session/stop`
7. POST `localhost:7878/recording` (binary webm blob, sessionId in header)

**Error handling:**
- If Electron not running: show "Not connected" in popup, buffer events in memory (up to 1000), retry POST when connection restored
- If `tabCapture` fails: show error in popup, abort session

### popup.html / popup.ts

Minimal UI:
- **Start Recording** button (disabled if not connected to Electron)
- **Stop Recording** button (shown during active session)
- Recording timer: `● 00:42`
- Status dot: green = connected to Electron, red = not connected
- Connection check: GET `localhost:7878/status` on popup open

## Electron: chrome-bridge.ts

New module. Uses Node built-in `http` — no new dependencies.

**Endpoints:**

| Method | Path | Description |
|--------|------|-------------|
| `GET` | `/status` | Returns `{ active, sessionId?, startTime? }` |
| `POST` | `/session/start` | Creates recording dir + SQLite DB, returns `{ sessionId, startTime }` |
| `POST` | `/session/stop` | Closes DB, marks session complete |
| `POST` | `/events` | Batch insert `ChromeEvent[]` into `chrome_events` table |
| `POST` | `/recording` | Receives webm binary, saves to `recordings/<stem>/<stem>.webm`, fires IPC to renderer |

CORS headers set to allow `chrome-extension://` origin.

Listens on `localhost:7878` only (not exposed on LAN).

Started in `main.ts` alongside existing IPC handlers. Stopped on `app.quit`.

## SQLite Schema: chrome_events

Added to the existing `.db` file alongside the `events` table (uiohook).

```sql
CREATE TABLE chrome_events (
  id             INTEGER PRIMARY KEY,
  type           TEXT    NOT NULL,   -- 'click','input','keydown','scroll','navigation'
  ts_ms          INTEGER NOT NULL,
  x              INTEGER,
  y              INTEGER,
  url            TEXT,
  page_title     TEXT,
  el_tag         TEXT,
  el_id          TEXT,
  el_text        TEXT,
  el_aria_label  TEXT,
  el_role        TEXT,
  el_placeholder TEXT,
  el_testid      TEXT,
  el_selector    TEXT,
  el_xpath       TEXT,
  el_classes     TEXT,   -- JSON array
  el_bbox        TEXT,   -- JSON {x,y,width,height}
  input_value    TEXT,
  key_combo      TEXT,   -- "Cmd+S", "Enter", "Tab"
  scroll_dir     TEXT,   -- "up" | "down"
  nav_from       TEXT,
  nav_to         TEXT
);

CREATE INDEX idx_chrome_ts ON chrome_events(ts_ms);
```

## Analysis Pipeline Changes

### RecordingPlayer — event list

When `chrome_events` exist for a recording, show them instead of uiohook events:

- Event label becomes: `"Add Patient" button` instead of `left (582, -664)`
- Selector shown as subtitle: `[data-testid="add-patient-btn"]`
- Navigation events shown as: `→ /patient-management/summary`
- Color coding unchanged (click=blue, key=green, scroll=gray, nav=purple)

### analyze.md prompt rows

Current format:
```
| 9 | 00:26.6 | mousedown | left (582, -664) | frame-26600.jpg |
```

New format (with chrome_events):
```
| 9 | 00:26.6 | click | "Patient 05-001" row [tr][data-patient-id="05-001"] | frame-26600.jpg |
```

### IPC additions

New handlers in `recorder-manager.ts`:
- `recorder:queryChrome(dbPath, fromMs, toMs)` → returns `ChromeEvent[]`
- `recorder:listFrames(framesDir)` → already exists
- `recorder:readFile(path)` → already exists

### analyze.md generation

In `RecordingPlayer.handleAnalyze()`: if `chrome_events` available, use them as the event source for rows (richer detail). If not, fall back to uiohook events (existing behavior). Logic: prefer chrome event within ±50ms of the key event timestamp.

## Build

`apps/chrome-extension/package.json`:
- `esbuild` bundles `background.ts`, `content-script.ts`, `popup.ts` → `dist/`
- Output is a standard unpacked extension directory, loaded via `chrome://extensions` in Developer Mode
- Turborepo task: `build` (runs esbuild)

No Electron rebuild needed (pure browser JS).

## Error Handling

| Scenario | Behavior |
|----------|----------|
| Electron not running | Popup shows "Not connected", events buffered in memory |
| `tabCapture` denied | Error shown in popup, session aborted cleanly |
| HTTP POST fails | Retry 3x with 1s backoff, then drop batch + log |
| Recording > 100MB | Warn in popup at 80MB, stop at 100MB |
| No chrome_events for recording | Fall back to uiohook events in player + analysis |
